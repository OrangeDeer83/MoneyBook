用 diff-reviewer agent 循環審查目前的修改，直到通過為止。

重點：$ARGUMENTS
（如果重點裡有 commit 範圍，例如 `05ad55c^..00a761d`，就審「範圍起點到目前工作區」的 diff：`git diff 05ad55c^ -- . ':!ci/ui/cases.json'`；沒有就審 `git diff HEAD`。）

每一輪：
1. 開頭先跟我說「🔁 第 N 輪（共最多 5 輪）：送審中…」。
2. 重新產生 diff（第 1 輪可以直接用下面附的），排除 `ci/ui/cases.json` 這種單行大檔。把 diff 完整放進 agent 的 prompt（太長就存成暫存檔，在 prompt 裡給路徑請它讀），不要附加我們之前的對話內容。第 2 輪起再附上「上一輪判定不修的項目與理由」，請 reviewer 不要重複提，除非理由有錯。
3. reviewer 的輸出原封不動貼給我，不要摘要。
4. 接著說「第 N 輪結果：Bug x、安全性 x、效能 x、風格 x」，每一項標「修／不修（理由）」。
   - Bug、安全性：一定要修，除非確定是誤判（要寫出根據，例如 diff 外的程式碼）。
   - 效能、風格：小改就修，牽涉大的列入 TODO.md。
   - 會改到畫面外觀或互動的，先停下來問我，不要自己改。
5. 修完進下一輪。

結束條件：
- ✅ 通過：reviewer 沒有提出新的 Bug／安全性問題，其他項目都已修或已說明不修。
- ⏸ 停下來問我：已經 5 輪、同一個問題連兩輪修不掉，或需要我決定的事。

結束後：
- 用 Artifact 做一頁總結：每一輪的問題、處理方式（修／不修＋理由）、改了哪些檔案，最後的結論。
- 修正不自動 commit，等我確認；確認後照平常流程 commit、push dev、跑測試。

!`git diff HEAD -- . ':!ci/ui/cases.json'`
